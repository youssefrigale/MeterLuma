# MeterLuma privacy information

Updated 2026-10-31, provider-connection revision 7, for the current desktop implementation. Publisher: Youssef Rigale, Morocco. Support and privacy contact: support@meterluma.com.

MeterLuma has no publisher account service, analytics, advertising, cloud sync, or automatic crash-report upload. It does not send your usage history or exports to the publisher. This describes the app. The meterluma.com website, downloads and support email are served through Cloudflare, which processes access logs and forwarded messages under its own privacy policy.

What changed in revision 7: Claude session and weekly limits are available through an explicit **Connections → Enable live Claude usage** choice. Existing revision-6 installations keep their history-only access until that choice is confirmed. The confirmation saves the `claudeLive` preference and revision 7 acknowledgement locally; turning it off returns Claude to history only. New installations still require the personal-use license acknowledgement before provider discovery. Automatic discovery, explicit disconnects, hidden providers and paused custom profiles retain their existing behavior.

## On your device

Optional Claude extra-usage amounts are read from the same usage response only when enabled there. Currency and decimal precision must be returned before minor-unit amounts can be displayed. They remain in memory, are hidden when stale/cached, and are stripped from persistent quota fallback snapshots. They do not enter local token-value Cost totals, usage exports or diagnostic reports. No separate billing/profile endpoint is queried.

The WebView stores appearance preferences, provider selections, profile labels and directory paths, history range, alert rules, and the accepted license version in local storage under meterluma.settings.v2. Dismissed alerts are kept under meterluma.alert-dismissals.v1. Paths and labels may contain personal information. Provider tokens and conversation content are not stored in these preferences. The license acknowledgement is local only, not an independently verified record of agreement.

For automatically detected or manually selected local Claude and Codex profiles, the native app reads their local session logs: Claude Code's projects folder (in ~/.claude, CLAUDE_CONFIG_DIR, or a profile folder you add) and Codex's sessions and archived_sessions folders (in ~/.codex, CODEX_HOME, or a profile folder you add). These files also contain conversation text. MeterLuma filters them locally and keeps only token counts, model names and timestamps, plus message or event identifiers used to avoid counting a record twice. It does not send conversations to the publisher or include them in exports. History is scoped to the selected directory on this device across sign-ins; it is not a verified account-wide billing record. The selected period is 30, 90, or 365 days. Scans are bounded (for example, at most the 2,000 most recently modified log files in the period); skipped or unreadable logs mark the result as partial.

History coverage: MeterLuma can only count logs that still exist. Claude Code deletes local transcripts after 30 days by default (its cleanupPeriodDays setting). Days before the first recorded day are shown and exported as "Not recorded", not as zero usage.

History results are cached in memory for 60 seconds. A per-file extraction cache keeps only dates, model names, record identifiers and token counts, never conversation text. The cache also persists under the app cache folder in history-extract-v1 so unchanged logs can be reused after restart. Cache filenames hash the provider and source path; the source path is not stored in the cache document. Entries are checked against source size, modification time, parser version and time zone, and token estimates are calculated again from current rates. Persistent cache entries are limited to 16 MiB each and pruned to 256 MiB and 10,000 files. Unix cache directories/files use owner-only permissions. Deleting this cache costs a rescan; the original provider logs remain under your control. Codex .jsonl.zst rollouts are decoded as bounded streams, with the same replay filtering as plain logs.

When you connect with an account token, the token briefly exists in the form and is cleared on submission. It is sent over the local native bridge and stored only after a successful provider lookup: Windows saves encrypted files under %LOCALAPPDATA%\app.meterluma.desktop\account-tokens-v1, protected by your Windows account using DPAPI; macOS saves generic-password items under the app.meterluma.desktop.account-tokens-v1 Keychain service. Only provider selections, never raw tokens, enter WebView preferences. A Codex account ID is stored with its encrypted token. Token connections pause this provider's local profiles; there is no fallback to local history or local sign-ins when a token fails or is disconnected. Other providers keep their explicitly selected connections.

MeterLuma keeps two small cache files in the app.meterluma.desktop folder of the operating system cache (Windows: %LOCALAPPDATA%\app.meterluma.desktop; macOS: ~/Library/Caches/app.meterluma.desktop):

- quota-snapshots-v1.json keeps the last successful Claude or Cursor quota or token-connected Codex quota for up to 16 connections: a hash of the profile path or a token-connection identifier, a SHA-256 fingerprint of the sign-in token, usage percentages, reset times, the plan label, Codex credit balance and available reset count when provided, included-usage permission and the fetch time. It holds no raw tokens, account names or conversations. When a refresh fails, the same sign-in's snapshot can be shown, labeled cached, for up to 24 hours. Expired quota windows, windows without a reset time once they are 5 minutes old, and entries older than 24 hours are removed from the file each time it is loaded or saved. A different sign-in never sees an old sign-in's snapshot.
- usage-cooldowns-v2.json keeps provider rate-limit deadlines: a hash of the profile path, a hash of the sign-in fingerprint, and the deadline. It holds no tokens or usage figures. A deadline follows the provider's Retry-After, with a minimum of 30 seconds and a maximum of 6 hours, and survives restarts. It applies only to the signed-in account, so signing in with a different account is not blocked. Expired deadlines are removed. There is no in-app reset: quit and delete this file, or wait at most 6 hours.

On startup MeterLuma deletes the two cache files left by earlier versions (quota-snapshots-v1.json and usage-cooldowns-v1.json in the MeterLuma folder of the operating system cache, which on Windows is also the install folder) and nothing else in that folder.

Provider details can estimate the API value of recorded Claude tokens locally, using Anthropic's list prices checked October 15, 2026. This uses the same token and model metadata and makes no network request. Estimates are labeled, use current standard global API rates and logged cache durations (five minutes if unspecified), and value fast mode at its published 2x rate on Opus 5.5, Opus 5 and Opus 4.8. They exclude tool fees, regional premiums, historical prices and discounts, and they are not subscription charges or bills. Tokens from models without a known price are left out of dollar amounts and counted separately. Codex token values are also calculated locally, using OpenAI Standard API prices checked October 26, 2026. They include cached-input discounts and supported per-request long-context tiers, exclude speed-tier multipliers and cache-write fees, and do not represent subscription credit charges. Exports may include the estimated value. Codex history excludes sessions explicitly marked with a non-OpenAI model provider; older logs without provider metadata remain device usage rather than verified subscription billing. Parse-cache schema version 2 prevents reuse of older counts across that change.

## Provider communications

Additional providers are disconnected by default. **Connections → More providers** requires a separate acknowledgment for each connection. API connections store only their provider ID, account label, enabled state and connection-consent version in preferences. The supplied API key or account access token is stored under `external-<provider-id>` in MeterLuma's existing Keychain service on macOS or its user-bound DPAPI token directory on Windows. It stays out of preferences and exports. A replacement is saved only after its usage lookup succeeds. The connection dialog stays busy until native secure storage completes; closing a dialog cannot cancel a Keychain write already in progress. Disconnect deletes MeterLuma's saved key, not the original provider sign-in.

The built-in [additional-provider catalog](src/additional/catalog.json) lists every enabled integration's fixed read-only endpoints and credential placement. These connections contact only the provider you select; regional MiniMax, Z.ai and Factory connections are separate and never try a key in another region. Currently the API hosts are api.deepseek.com, openrouter.ai, api.elevenlabs.io, api.synthetic.new, api.venice.ai, crof.ai, portal.nousresearch.com, api.pioneer.ai, api.github.com, cli-chat-proxy.grok.com, api.kimi.com, www.minimax.io, api.minimaxi.com, api.z.ai, open.bigmodel.cn, ai-gateway.vercel.sh, api.neuralwatt.com, api.commandcode.ai, opencode.ai, server.codeium.com, ampcode.com, ollama.com, api.factory.ai, api.eu.factory.ai, cloudcode-pa.googleapis.com, app.warp.dev, www.perplexity.ai, api.fireworks.ai, cloud.zed.dev, bailian-singapore-cs.alibabacloud.com and bailian-cs.console.aliyun.com. Some usage endpoints are undocumented and can change. MeterLuma reads no browser cookies, runs no inference and does not implement OAuth renewal. Installed-CLI readers described below manage their own sign-in and local state. Response account/org identifiers and raw response bodies are discarded; only supported plan, amount, quota and timestamp fields reach the interface. A GitHub organization-managed seat may expose a personal credit count without a personal percentage quota; MeterLuma does not request organization billing permissions.

Windsurf and Devin use only the fixed GetUserStatus Connect RPC on server.codeium.com. The selected companion API key is placed in the request metadata, with MeterLuma identified as the client; the app does not change the companion sign-in or contact a custom server from its configuration. Amp uses only userDisplayBalanceInfo at ampcode.com/api/internal; Gemini uses only retrieveUserQuota with the supplied Cloud project; Antigravity uses only retrieveUserQuotaSummary at the production Cloud Code host; Warp sends only the fixed GetRequestLimitInfo GraphQL query. These POSTs retrieve metadata and send no prompts or mutations. Other additional API connections use GET requests, except the fixed Alibaba quota-query forms described below. Gemini project IDs, Fireworks account IDs and numeric Zed user IDs stay with the token in secure storage, not preferences. Zed sends its user ID and access token in the Authorization header required by its account API and reports only personal edit-prediction usage. Alibaba international and China connections send only the fixed Coding Plan quota query as a URL-encoded form to their separate console gateways; they require a supplied console access token, not an inference key. MeterLuma does not start the Model Studio CLI, read browser sessions, run inference or renew that token. Fireworks queries the last 30 UTC calendar dates and keeps rated costs separate from balance and Fire Pass quota.

At most four additional API lookups and two local/CLI readers run concurrently. Additional-provider HTTP requests verify TLS, follow proxy settings, reject redirects, time out after 15 seconds and bound decoded response bodies to 1 MiB. Successful values are kept in memory for about five minutes for the same credential. Failed refreshes can show the same credential's labeled snapshot for at most five minutes, excluding expired quota windows. Additional quotas and balances are not persisted. `additional-cooldowns-v1.json` in the app cache stores only provider identifiers, hashed credential fingerprints and bounded Retry-After deadlines, surviving restarts. Deleting a connection removes its deadline. Provider-reported amounts retain their returned currency or non-monetary unit and are excluded from local Cost estimates.

Xal and Zcode connections read local metadata only after individual opt-in: `$XAL_HOME/usage/*.jsonl` (default `~/.xal/usage`) and `$ZCODE_HOME/cli/db/*.sqlite` (default `~/.zcode/cli/db`). Zcode databases are opened read-only. Scans keep token counts and dates for the last 30 local calendar days, deduplicate Xal request IDs, and discard record content after extraction. These counts are device history, not account ownership, subscription status or invoices. They are held in memory, not written to a separate history cache or included in usage exports. Unreadable/malformed records or scan limits produce a partial-history notice; a missing source does not become a fabricated zero. Disconnect stops reads and preserves original logs and databases.

Pi reads `$PI_CODING_AGENT_DIR/sessions` (default `~/.pi/agent/sessions`). Muse reads `$XDG_DATA_HOME/muse/sessions` (default `~/.local/share/muse/sessions`). Both scan bounded JSONL files and deduplicate replayed records, keeping metadata only. Pi uses reported `totalTokens`, including usage/compaction/branch-summary entries. Muse uses reported `total_tokens` or recorded input plus output; cache and reasoning are not added separately. Cline reads request-level ledgers under `$CLINE_DATA_DIR/tasks` (default `~/.cline/data/tasks`) and VS Code's `Code/User/globalStorage/saoudrizwan.claude-dev/tasks` beneath the platform configuration directory. Undated deleted/subagent aggregates are excluded and flagged partial. These readers do not infer account ownership or billing, and do not silently fold tool usage into Claude or Codex totals.

JetBrains reads the newest `JetBrains/<IDE-version>/options/AIAssistantQuotaManager2.xml` beneath the platform configuration directory, rejecting expired windows or a file older than 24 hours. Kiro reads only the `kiro.kiroAgent` row in its IDE state database, opened read-only, accepting dated quota no older than 15 minutes. Both display the source timestamp and a cached warning. No credential is needed for these saved-quota readers.

Qoder starts its installed CLI with streamed control input and sends only `initialize` and `get_usage_info`, with no user prompt, project settings, built-in skills, MCP servers or session persistence. It rejects interactive action requests. BytePlus starts the installed Ark CLI for `auth status --format json`, then `usage plan --format json` only when logged in; it never starts login, selects a different profile or requests another user's seats. Automatic update notification is suppressed and automation caller metadata is retained. CLI stdout is bounded, deadlines stop stuck readers, and macOS/Unix readers own a process group so worker children are stopped as well. CLI credentials are managed by those CLIs; MeterLuma saves no copy. New CLI connections remain individually opt-in.

Claude: history-only mode reads Claude Code's local log files and keeps only token counts, model names, dates and message identifiers; conversation text is discarded and never sent. Enabling live usage additionally reads Claude Code's existing OAuth access token and saved subscription-type label. On macOS each selected profile checks its own path-hashed `Claude Code-credentials-<hash>` Keychain services through the macOS security tool. Only the default `~/.claude` profile may also use the unscoped `Claude Code-credentials` item. Invalid or expired Keychain records do not hide a valid `.credentials.json` in that same profile. Custom profiles never borrow the default Keychain account. Credential files are bounded to 64 KiB and, on Unix systems, must not be readable by other users. Missing sign-ins or credentials lacking usage access require signing in through Claude Code. Expired access is renewed automatically on macOS as described below.

The Claude access token stays in native process memory and is sent only to `GET https://api.anthropic.com/api/oauth/usage`, with the `anthropic-beta: oauth-2025-04-20` header and MeterLuma's own User-Agent. This is an undocumented usage endpoint and may change. The app never sends model prompts or redeems resets. On macOS, expired access automatically starts the installed official native Claude Code CLI in a private empty workspace, in safe mode with no prompt, hooks, tools or MCP servers. MeterLuma never accepts workspace-trust or login screens. Claude Code owns credential rotation and storage; MeterLuma rereads the selected profile and terminates the temporary process when renewal completes or its 25-second polling deadline is reached (Keychain reads have their own bounded timeout). Failed renewal attempts are limited to once a minute and retried automatically. Missing or revoked sign-ins may still need signing in through Claude Code. It does not read Claude Desktop's encrypted login or browser cookies. Requests have the same verified TLS, no-redirect policy, 15-second timeout, 1 MiB response bound, credential-scoped snapshots and rate-limit backoff as Cursor. While live Claude usage is enabled, MeterLuma checks once a minute, or every 30 seconds when the Session has 25% or less remaining and is not yet exhausted. The shared native success cache expires just before that interval. Manual refresh bypasses the success cache, but never a provider rate-limit cooldown. Only reported Session and Weekly values are shown; missing values remain unavailable. Cached limits are labeled. The plan label comes from the saved Claude Code login, not a live billing-status lookup; it cannot establish whether billing is active or paused. Recorded device history is independent of the current subscription login and remains visible if usage lookup fails. Fresh opt-in live Claude quotas can trigger in-app threshold alerts; cached, expired, demo and history-only values do not.

Codex: Local-profile quota lookup runs the installed official Codex CLI against that selected profile. For an account-token connection, MeterLuma passes your supplied ChatGPT OAuth access token and account ID to the official CLI's experimental chatgptAuthTokens mode over stdin, not command-line arguments or environment variables. The CLI uses a separate temporary home and working directory; MeterLuma does not load your usual auth.json, config.toml, sessions or workspace configuration for this connection. It requests only initialization, token authentication and subscription rate limits, never prompts or inference. Supplied tokens are not renewed automatically; an expired token requires replacement in Connections. Lookups are bounded by 30 seconds (20 seconds for a local profile) and 1 MiB of output, and the child process is stopped afterwards. The temporary profile is removed after the process exits. The CLI communicates with OpenAI according to its own policies. An up-to-date official CLI supporting external tokens is required.

Cursor (Unofficial): With an account-token connection, MeterLuma uses only the token you enter. With an automatically detected or manually selected local-profile connection, it reads Cursor's existing access token, read-only, from Cursor's local state database (Cursor/User/globalStorage/state.vscdb). Encrypted Cursor safeStorage credentials are unlocked read-only in the native process: macOS v10 uses the existing "Cursor Safe Storage" Keychain password and CommonCrypto; Windows uses user-bound DPAPI. No decrypted credential or password is written back. Unknown or malformed encrypted formats are rejected instead of being sent as bearer tokens. On macOS, for the default profile only, a missing database token falls back to the Keychain item "cursor-access-token". During each lookup the token is used in native process memory and sent only to https://api2.cursor.sh/aiserver.v1.DashboardService/GetCurrentPeriodUsage, with the User-Agent MeterLuma/<app version>. This is an undocumented Cursor endpoint that is not endorsed by Cursor and may change or stop working without notice, so the app labels it Unofficial. TLS is verified against the operating system's trusted certificates plus bundled roots, redirects are not followed, requests time out after 15 seconds, responses are limited to 1 MiB, and errors omit raw response bodies and token values. A successful result is reused for 5 minutes for the same sign-in. MeterLuma never renews or writes Cursor credentials. Cursor receives the access token and ordinary request and network metadata under its own policies.

Requests follow your proxy settings (the HTTP_PROXY, HTTPS_PROXY, ALL_PROXY and NO_PROXY environment variables, otherwise the manual proxy configured in Windows or macOS), so a configured proxy also sees them. Your network provider and each contacted service may receive ordinary connection information such as an IP address.

Updates: a build without an updater configuration never checks for updates. If the publisher enables updates in a release, that build contacts the publisher's update address about 30 seconds after start, then about once a day (after a failed check, it retries every 15 minutes until one succeeds), and when you choose "Check for updates". The request reveals your IP address and may include the app version, operating system and processor type. It sends nothing about your providers or usage, and an update installs only after you confirm. Published release builds use `https://downloads.meterluma.com/latest.json`, a static file on the publisher's Cloudflare account; Cloudflare receives the connection details of each check, including your IP address, under its own privacy policy. The publisher does not run an update server or receive per-check logs beyond Cloudflare's aggregate statistics.

Official status and usage pages open in your default browser only when you choose them.

## Alerts, exports, and deletion

Alerts appear in the app while it is running. They use fresh Codex or Cursor quotas only, never cached or sample values. There are no push services or notification uploads. CSV and JSON exports are created only when you request them, through a native save dialog. Exported files can reveal usage patterns, model names, and your profile labels; you control where they are saved and whether to share them. Exports omit credentials, local directory paths and conversation content.


Overview card collapse choices are stored in meterluma.settings.v2 as up to 80 scoped provider/opaque connection IDs. These keys do not copy account labels or directory paths. They are excluded from display-preference exports/imports and diagnostics. Collapsing changes only appearance: it does not pause refresh or mute alerts. Reset preferences clears collapse choices; Restore overview layout changes only card collapse, provider orders and menu-window selection, with in-page Undo. Theme, visibility, spacing, refresh, notification choices, connections and credentials are kept.

Provider reordering stores the existing core provider order and up to 44 known additional-provider IDs in meterluma.settings.v2. Dragging changes display order in Connections, Overview and the sidebar; it does not change sign-ins, credentials, connection enablement or refresh sources. Additional-provider order stays on this device and is excluded from display-preference transfers and diagnostics. Restore overview layout clears both orders, and its Undo restores them. No labels or local paths are copied into ordering metadata.

Settings backup exports only display preferences: appearance, visibility/order, refresh cadence, timers, history window, projection, compact spacing and menu-window selection. Import reads only the file chosen in the OS picker, bounds it to 64 KiB, validates its version/fields/values, and previews changes before applying them. Connections, account labels/paths, tokens, alerts, consent and the system login setting are neither transferred nor changed by import. Custom keyboard shortcuts and the session-only stay-open choice are also excluded. Undo restores the previous display preferences. Exports use a temporary file in the chosen destination folder and replace an existing export only after a complete write.

Help diagnostics retain at most 20 frontend lookup timing/status records in memory. Provider IDs are limited to the built-in catalog. No lookup arguments, account labels, local paths, credentials, raw errors/responses, quota values, token totals or balances are retained in these records. The preview adds coarse platform/app version and availability/cache/partial states. It is saved locally only when you choose Export diagnostics, never uploaded. Clear diagnostic history removes the recent timing records; quitting clears them. Frontend elapsed time includes waiting and does not prove that a timed-out native operation has stopped.

Optional Mac desktop notifications use UserNotifications authorization read from macOS, with a prompt only after the explicit enable action. They start off and are excluded from display-preference imports/resets. The app sends the provider, quota name and a fixed event description to the local OS notification service, without account labels, token totals, amounts or credentials. Focus, foreground behavior and OS notification preferences control actual appearance. Known live quotas can trigger low-allowance, custom-threshold, worsening-pace and reset reminders; cached/stale/error/history-only readings do not. No additional provider request, email or publisher upload is introduced.

Local notification history records hashed event IDs and expiry times under meterluma.notification-history.v1 (up to 1,000), plus hashed metric IDs, coarse pace levels, episode/pending-level state and expiry times under meterluma.notification-pace.v1 (up to 512). Raw labels, paths, quota figures, usage/cost totals and credentials are not stored there; these stores are excluded from preference/usage exports and diagnostics. Attempts are saved before OS dispatch to prevent replay after an uncertain result or restart. Failures pause notifications; Clear notification history removes both stores and allows current events to be attempted again. A storage failure prevents dispatch. Turning notifications off stops future requests but does not remove already delivered OS notifications. Windows notification delivery is unavailable in this build; existing in-app alerts remain. See [notification behavior](docs/notifications.md).

Start at login is enabled automatically on the first launch of an installed build, including upgrades to this default, using MeterLuma's own per-user LaunchAgent on macOS or the current user's Run entry on Windows. A local initialization marker prevents later launches from overriding a subsequent opt-out in MeterLuma or system settings. Reading the current state does not change it. It starts quietly and is excluded from preference imports/resets. Turn it off in Settings before deleting the Mac app or uninstalling if you want to remove that registration. Real login/reboot and Windows uninstaller cleanup remain pending QA.

A custom global keyboard shortcut is off by default. Its chosen Command/Ctrl + Shift or Alt + letter combination is stored locally and registered with the OS while MeterLuma runs, including after an app restart. The app receives that registered shortcut, not general keystroke history. A conflicting key does not replace the existing binding; Remove shortcut unregisters MeterLuma’s binding. Preference imports/resets do not register or remove shortcuts. The stay-open panel choice changes only whether the panel hides on focus loss, is kept in memory, and turns off on app exit. Neither control sends data over the network.

Remove a profile or disconnect a provider to stop reading that source. Disconnecting a token connection removes its protected token and cached quota/cooldown from MeterLuma. It does not sign you out of a provider, revoke its token at the provider, or delete original logs. Disconnected providers are excluded from later automatic detection until you explicitly reconnect. Reset preferences returns display settings to their defaults and keeps connections, local accounts, alerts and license acceptance. Quitting clears in-memory results. Delete exported files separately.

Uninstalling on Windows removes the app. If you also tick "Delete the application data" in the uninstaller, it removes the %LOCALAPPDATA%\app.meterluma.desktop and %APPDATA%\app.meterluma.desktop folders, which hold the saved preferences (WebView storage) and both cache files. Without that option, those folders remain. On macOS, deleting the app does not remove its data: the ~/Library/Caches/app.meterluma.desktop folder and the WebView storage macOS keeps for app.meterluma.desktop under ~/Library remain until you delete them. Saved Keychain account tokens also remain after deleting the Mac app; disconnect them in MeterLuma before uninstalling, or remove its named Keychain items yourself. Uninstalling never touches exported files, provider logs or provider sign-ins, and operating-system backups may keep copies. MeterLuma does not erase provider data.

## Support and applicable privacy rights

Do not send credentials, conversation logs, or unredacted screenshots in support requests. If you contact the publisher, the publisher and mail service will process what you send to handle that request. The mailbox provider, retention period, applicable lawful basis, any international transfers, and any required Moroccan CNDP formalities must be confirmed before support opens. This notice does not represent that those operations have already been configured or legally cleared. Contact the publisher for access, correction, deletion, or other applicable rights concerning data the publisher actually holds.

Children's data, additional telemetry, cloud sync, support uploads, a new update host, or a changed hosting setup require a fresh assessment and updated information before being introduced.
