# Try the MeterLuma beta

This is an internal, unsigned prototype. Read and accept the license/privacy information, then connect a local provider profile you already use. Release builds use real data only and hide demo controls; sample data remains a development-preview tool. It is free for personal, noncommercial use only under [LICENSE](../LICENSE); selling and redistribution are prohibited. Share the owner's official link rather than copies. Selected Claude Code credential-file tokens support guarded renewal; other credential sources remain read-only. Cached quotas are labeled with their original fetch time.

## Windows

The current local beta is in `artifacts/releases/windows-beta-2026-10-15/`. Extract `MeterLuma-Windows-Portable.zip` and run `MeterLuma.exe` from its folder, keeping both DLLs and the notices beside it. Alternatively, use `MeterLuma-Windows-Setup.exe`. These replace the older Windows artifacts in the parent directory. Microsoft WebView2 is required; it is present on the owner machine.

The October 15 build uses the local GNU LLVM toolchain and includes its required runtime DLLs. Native runtime checks passed for hidden startup, fresh live defaults, consent and bundled notices, consent synchronization between windows, real Codex quotas, 365-day recorded activity, export availability, and persisted alerts/history preferences. The current Codex npm executable layout is supported. Provider details now use compact combined usage rows, an inline trend, and up to five model shares with expandable extras. Both themes and the expired-login layout fit at 360 by 660 logical pixels in browser tests; the native Claude recorded-activity layout also passed this check. Claude most recently returned HTTP 429 with a one-hour Retry-After. The app now shows Rate limited, preserves the deadline across refreshes and restarts, and keeps recorded history separate from live quota availability. Successful current Claude quotas remain unverified until the provider allows another request. Cursor had no readable local sign-in. Personal usage figures and credentials are excluded from the check report.

Installer installation/uninstallation and the native export save dialog have not been manually exercised. Other taskbar locations, auto-hide, multiple monitors, display scales, actual tray clicking, and the standard MSVC release still need checks. Earlier Windows placement checks do not certify every configuration.

## Mac

The existing `MeterLuma-Mac.dmg` contains both Intel and Apple Silicon builds from October 13. It predates the current free features and provider changes and is not the matching current beta. Rebuild the current source on a Mac runner, then test GUI behavior and actual local sign-ins on real hardware. Signing and notarization are not configured yet.

## Explore the app

1. Launch the app and click its menu-bar / tray icon. The compact panel should open near the icon; the full dashboard should start hidden. Confirm the panel says **Live**. Without a connected sign-in it should show setup, with no invented usage. Connecting a provider should show its reported quotas or a sign-in error.
2. Open **Options → Settings**, change the theme, and close/reopen the window to check that preferences persist. The Left / Used preference affects both the popup and the full dashboard. Check relative / absolute reset timers, clock format, refresh intervals, and provider ordering.
3. On Windows, check that the panel's bottom aligns exactly with the taskbar's top, including after closing and reopening it. Use the sidebar to select Overview, a provider, Costs, Help, or Settings. In Costs, check Today / Yesterday / 30 Days; scroll provider details and confirm the Options footer stays visible. Check that changing pages resizes the popup while preserving taskbar alignment. **Options → Settings** stays inside the popup; Connections and Open dashboard open the corresponding full-window page. Check provider visibility and theme changes propagate to the panel. Clicking outside hides it. Check Windows at multiple display scales and macOS on Intel and Apple Silicon; a successful build alone does not verify tray placement or focus behavior on hardware.
4. In Connections, select a provider's **Connection options**, then **Use local profile**. You must already be signed in to Claude Code, Codex CLI, or Cursor. The README lists supported local profiles and limitations. Claude and Cursor quotas use existing local credentials and fixed usage endpoints. Codex quotas use its installed official CLI.
5. Compare the displayed limits and reset time with that provider's own usage screen. Record only the provider, plan, OS, and any error message when reporting a problem. Do not include credential files or tokens.
6. Disconnect the provider in MeterLuma and check that its data disappears. This does not log you out of the original provider app.
7. Use **Quit MeterLuma** in the tray menu to exit fully. Closing the dashboard window keeps the app in the tray.

Live quotas show their actual successful fetch timestamp. Claude/Cursor credentials stay inside the native process and are never copied into settings or a MeterLuma credential store. Claude Code credential-file renewal updates only its token/expiry fields after generation checks. Cached usage snapshots contain credential hashes and usage metadata, not raw tokens. Codex delegates authentication to its official CLI. Actual billed spending remains unavailable. Claude details combine recorded tokens with labeled estimates of API value for known model prices. These use current standard global rates and logged cache durations, not subscription charges; unknown-model day/period dollar totals are omitted. Claude and Codex recorded token histories are read from local session logs, clearly scoped to this device across local sign-ins. They remain available even when quota credentials need renewal. Choose 30/90/365 days in Activity and test both exports. Read limits, unreadable or oversized logs are indicated as partial. No message content or credentials are returned with history.

## Release limitations

Multiple existing local profiles, in-app quota alerts, longer recorded history/trends, and CSV/JSON exports are included free for personal use. Test profile isolation/removal, threshold crossing, stale-quota suppression, cancelled save dialogs, and exports with partial/missing history. There is no paid edition or checkout in the current release scope. There is no automatic updater or startup-at-login control yet. Real-account tests, platform credential variants, multiple monitors, DPI scaling, sleep/wake, and minimum supported OS versions require further QA before public release.
