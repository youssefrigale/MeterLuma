# MeterLuma legal issue review — 2026-10-15

This is a practical issue review of the repository and published primary sources, prepared with AI assistance. It is not an opinion from a Moroccan advocate, does not establish an attorney-client relationship, and does not certify worldwide compliance. The owner identified himself as Youssef Rigale, located in Morocco, and supplied support@meterluma.com as the intended contact. Domain ownership, mailbox operation, business status, and a public service address have not been verified.

## Result

**Public release is not legally cleared.** The chosen model is proprietary software free for personal use, with commercial use and redistribution restricted. Publishing source to a public GitHub repository conflicts with a strict prohibition on all copying/forking there. Native distribution, provider authorization, required notices, owner disclosures, and applicable consumer/privacy obligations must be assessed for the actual release and intended markets.

## Findings and changes

1. **License scope and ownership.** LICENSE 1.1 identifies Youssef Rigale and permits private personal use, backups on the user's own devices, and private source modifications if source is supplied. It excludes user data/exports and separately licensed components from the restrictions. It prohibits commercial, professional, business and organizational use, selling, sharing copies and modified distributions. This matches the owner's stated preference; it is not an open-source license under the [Open Source Definition](https://opensource.org/osd).

2. **Mandatory rights and contract formation.** The license preserves non-waivable protections, software exceptions and competent court rules, includes severability, and does not impose arbitration or attempt to revoke earlier grants retroactively. Moroccan law is the stated governing law, subject to mandatory protections elsewhere. A first-use checkbox precedes local data access and the text is available in-app and packaged with the app. The acknowledgement is stored locally; it is not proof of identity or an independent agreement record. Country-specific enforceability and required publisher/address disclosures still need an advocate's assessment. For example, the EU [Software Directive](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32009L0024) contains mandatory software exceptions; a blanket restriction cannot simply remove applicable statutory rights.

3. **Claude credentials - policy uncertainty, not an established usage-monitoring ban.** [Anthropic's authentication documentation](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) contains broad restrictions concerning subscription credentials. The earlier review overreached by treating those provisions as enough to require disabling this usage-only connector. No specific prohibition or explicit exception for this exact read-only use case was established. [OpenUsage documents](https://github.com/robinebers/openusage/blob/main/docs/providers/claude.md) using an existing local sign-in with the OAuth usage endpoint. At the owner's instruction, that general request approach is restored in MeterLuma with local-only credential handling, fixed HTTPS destinations and bounded responses. This is an implementation decision with unresolved contractual interpretation, not a claim of provider authorization or a finding that OpenUsage has special permission. MeterLuma makes no inference requests. The current implementation can renew selected Claude Code credential-file tokens through the same provider OAuth refresh flow, with guarded write-back; Keychain/Desktop and Cursor tokens remain read-only. This additional behavior is disclosed in privacy revision 3 and does not resolve provider-policy uncertainty.

4. **Codex and Cursor.** Codex keeps its official CLI's documented [app-server rate-limit interface](https://learn.chatgpt.com/docs/app-server). [OpenUsage documents](https://github.com/robinebers/openusage/blob/main/docs/providers/cursor.md) reading Cursor's local sign-in and using its dashboard usage RPC. MeterLuma restores that general usage-request path. [Cursor's terms](https://cursor.com/terms-of-service) contain broad extraction restrictions; their application to this precise local, user-selected usage lookup remains an interpretation question. The existence of OpenUsage demonstrates a working implementation, not blanket legal permission. The previous pause was a precautionary product choice and has been reversed. No provider-approval claim is made.

5. **Third-party copyrights and trademarks.** The resolved inventory contains 510 components across frontend runtime dependencies, Rust transitive/build/platform crates, and native WebView2/LLVM runtime supplements. THIRD_PARTY_NOTICES.txt preserves collected texts, provenance and exact source archive links, including MPL source availability. The generator reports no unresolved notice entries; sources include archive files, pinned upstream notices and identified companion project license texts. This inventory is not an independent legal audit. No third-party license is replaced by MeterLuma's no-redistribution term. Packages not shipped on a given platform may be listed. An exact-binary review remains necessary, especially for source-availability conditions and external system components. Upstream logo copyright permission does not establish trademark permission; provider names/logos must be referential, avoid implied endorsement, and be checked against each provider's brand rules or replaced with original neutral symbols before release if permission is not established.

6. **Privacy and Morocco.** PRIVACY.md describes the local processing, stored directory labels/paths, bounded log scanning, CLI communications, exports and deletion controls. No analytics or publisher upload service is implemented. Do not infer that this eliminates all obligations: future support emails, hosting logs or telemetry introduce separate processing. The [Moroccan CNDP guidance](https://www.cndp.ma/conditions/) requires appropriate purposes, proportionality and transparency for personal-data processing within its scope. Identify actual controllers, processors, retention, international transfers, and any applicable notification/authorization before support/hosting goes live. Applicability of Moroccan, EU/UK or other privacy rules depends on actual operations, audience and data flows; no blanket exemption is claimed.

7. **Public GitHub contradiction.** [GitHub's public-repository terms](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#5-license-grant-to-other-users) grant platform view/fork rights. Keep source private while strict no-redistribution is required. An owner-controlled download site can distribute the owner's binaries under the personal-use terms. A public project showcase linking official downloads needs its own compatible content terms and must not accidentally publish restricted source.

8. **Launch claims.** Do not advertise legal approval, provider affiliation, account-wide billing, live dollar spending, guaranteed alerts, or support that has not been configured. The former paid features are free personal-use features; history is recorded device/profile activity, accounts are separate existing local directories, alerts are in-app while running and require fresh available quotas, and exports contain only selected usage metadata. Signing/notarization and verified installations are separate technical release requirements.
